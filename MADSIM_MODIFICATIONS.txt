MADSIM MODIFICATIONS
====================
Change log of modifications done to madsim

Edited files:
  cmod/phy_top/include/phy_spec.h

================================================================================
1. PhyLtsm.h -- one-cycle hold after a sideband handoff
================================================================================
Status: Fixed upstream in 7fd08862 by combinational sideband ready propagation.
The local tx_cooldown workaround has been removed.

Bug:
  Sideband::DriveTx returns ready to the LTSM through a register, so the ready
  PhyLtsm::Run reads is a cycle stale. On the cycle the CDC takes a message its
  in1_rdy drops, but the LTSM still sees the old high ready, takes sb_tx_msg to
  be clear, and overwrites it. sent_req_ / sent_resp_ are set in SendMsg rather
  than on handoff, so the message is recorded as sent and never retransmitted.

  Hits any state that answers a request and issues its own back to back, which
  is every symmetric handshake here. Confirmed, each with sent_req_ set and
  nothing on the wire:

    MBINIT.REPAIRCLK        {done req}
    MBINIT.REPAIRVAL        {done req}
    MBTRAIN.VALTRAINCENTER  D2C {lfsr clear req}
    MBTRAIN.VALTRAINCENTER  D2C {results req}

  The lost request also stops the local pattern reader,
  so no result is produced and madsim waits on a response to a request it
  believes it made.
Why not a UcieTL fix:
  The message is lost inside madsim between SendMsg and the bump. The partner
  cannot request a retransmission, having no way to know a message was ever
  intended, and madsim will not retransmit because sent_req_ already says the
  request went out.

Outcome without fixes:
  Before, MBINIT.REPAIRCLK never completed without a UcieTL workaround.
  After, the lost {done req} reaches the wire and training runs unaided through
  MBINIT and eight MBTRAIN substates, faster than with the workarounds in UcieTL

================================================================================
2. phy_spec.h -- two timeout constants
================================================================================
Both in cmod/phy_top/include/phy_spec.h, namespace phy_spec:

  line 33   const int kStateTimeoutCycles
              was  10000
              now  6400000

  line 36   const int kSbTrainingTimeoutCycles
              was  8 * kSbTrainingPhaseCycles   (= 3072)
              now  6400000

Why:
  The spec allows 8 ms per link-training state, which at the 800 MHz sideband
  clock is 6,400,000 cycles. UcieTL uses that (LinkTrainingSM.scala:99-100);
  madsim's 10000 expired during UcieTL's first SBINIT phase, forcing TRAINERROR
  and a retrain. Matched so the partner reports a stuck link first.

Outcome without fixes:
  madsim declares TRAINERROR inside SBINIT, before UcieTL has finished its own
  reset wait. Nothing trains and no flit crosses in either direction.

================================================================================
ISSUE, fixed upstream -- dropped sideband requests
================================================================================
Status: Fixed upstream in 250baa39 by retaining requests until handled and
correcting request acknowledgement during state transitions. The retry in
Berkeley's SidebandMessageExchanger.scala has been removed.

Every LTSM substate module clears an incoming request whether or not it
services it. A request that arrives before the local die reaches the state that
handles it is dropped, nothing retransmits it, and both dies wait out the
training timeout. Responses are fine..their clear sits inside the guard.

mb_init_repair_clk.h, top of Step():

    bool rx_result_req = response_tracker.result_req;
    response_tracker.result_req = false;      // cleared either way
    ...
    case REPAIRCLK_RESULT_HANDSHAKE:
        if (rx_result_req && !sent_resp_) {
            if (rx_done_seen_) {              // only serviced when ready

Scope:
  16 files under cmod/phy_top/PhyLtsm/LTSM, about 45 sites. Every MBINIT and
  MBTRAIN substate module, plus SBINIT.

Outcome without fixes:
  Latching result_req gets past the result handshake, then the run stalls on
  done_req in the same substate. Latching that too gets past REPAIRCLK, then it
  stalls in MBINIT.REPAIRVAL. Every module needs the fix before a link trains,
  which is why this is worked around instead.

Previous workaround:
  SidebandMessageExchanger.scala re-sends an unanswered request after a dwell.

  UCIe does not define sideband message retransmission, so this retry is not
  spec behaviour. A conformant partner waits forever; anything that gets past
  the defect is non-conformant.

================================================================================
Interface updates
================================================================================
madsim now exposes RVA data/valid/ready ports and sideband forwarded clocks.
src/madsim_die.h binds the new ports. src/ucie_cosim_top.sv connects sideband
data and clocks directly, and src/ucie_sb_shim.sv is removed. The monitor and
probe sample sideband bits on falling forwarded-clock edges.
